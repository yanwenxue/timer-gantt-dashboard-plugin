# timer-gantt-dashboard-plugin
飞书-秒级甘特图

## 飞书市场发布

飞书部署读取 `package.json` 中的 `output: "dist"`。提交审核前，在仓库根目录执行：

```bash
npm ci
npm test
npm run build
git add dist
```

将源代码和最新的 `dist/` 构建产物一同提交并推送到 GitHub，确保仓库中包含 `dist/index.html` 及其引用的 `dist/assets/` 文件。每次修改源代码后都需要重新构建并提交产物。

仓库只保留 `dist/` 一份构建产物，供飞书市场部署和 GitHub Pages 共用。构建资源使用相对路径，以支持飞书 CDN 部署。

## GitHub Pages 发布

推送到 `main` 后，`.github/workflows/pages.yml` 会安装锁定的依赖、执行测试并重新构建，再检查构建结果是否与提交的 `dist/` 一致。校验通过后发布到 GitHub Pages；若遗漏或提交了过期产物，工作流失败并保留上一次成功发布。仓库不再维护 `docs/`。

本地构建并提交后，可运行 `npm run check:dist` 检查产物与提交状态及入口引用的资源是否完整。

仓库 Settings → Pages → Source 使用 `GitHub Actions`。

在线地址保持不变：https://yanwenxue.github.io/timer-gantt-dashboard-plugin/ 。已引用该地址的飞书仪表盘无需重新添加。

## 数据与交互

- 仅需任务名称、开始时间、结束时间字段，耗时字段可选，无需添加或选择“记录唯一标识”。按记录自带的系统 ID 保留独立执行，同名、同时间的记录不会被合并。
- 数据范围以所选数据表或视图为准，不联动仪表盘全局筛选；图内任务类型和时间范围筛选仍可使用。创建、配置、展示和全屏均通过 Base SDK 读取原始记录，不调用 Dashboard 聚合数据 API。
- 原始记录通过当前 SDK 的 `getRecords` 每页读取 200 条，按 `hasMore` / `pageToken` 继续读取；选定视图时每页都保留视图范围。分页失败时显示错误，不展示截断的数据。
- 一组 `dataConditions` 保存表和视图供宿主复制映射，字段 ID 保存于 `customConfig.sourceFields`。复制 Base 时字段 ID 保持不变，使用宿主映射后的表 ID。
- 旧版字段名称、字段 ID，以及 v2/v3 配置均可直接读取，无需因版本升级而重新选择字段；已废弃的唯一标识配置会被忽略。
- 首次使用会寻找包含任务名称及两个日期字段的表，已有表 ID 或旧配置中的表名优先。配置缺少必需字段时，编辑页仍可加载表结构并重新选择，校验通过后才能保存；展示态仍明确报错。
- 未选择视图时使用全表范围；选择的视图失效时提示错误。配置字段按选定视图顺序排列，隐藏字段附在末尾，提供搜索和类型标记。
- 耗时字段可留空，按结束时间减开始时间计算；单元格为空或不是有效非负数字时也按时间差计算，显式的 `0` 保留。
- 名称为空、时间无效或结束早于开始的记录会跳过并提示数量。真实数据为空或读取失败时不混入示例数据；独立打开页面才展示内置演示数据，可选择“全部”查看。
- 刷新和主题切换保留有效缩放位置；切换数据表、视图或时间范围时重置。悬停时间轴显示秒级时间、参考线及相交任务。
- 最近 3 天、最近 7 天和今天使用同一个时钟计算统计和横轴，每分钟及手动刷新时更新。
- 切换表时禁用旧字段，保存前校验字段及视图是否有效；已失效的选择会提示重新选择。初始化失败后可点击刷新重试。
- 保留 `onDataChange` 和 `onConfigChange` 监听；通过表的 `onRecordAdd`、`onRecordModify`、`onRecordDelete` 更新记录。展示态跟随配置变更更新数据源，编辑态保留未保存的本地选择。卸载时清理订阅，旧请求不能覆盖新结果。
- 宿主语言、主题初始化及数据加载完成后，等待 ECharts `finished` 事件再通知 `setRendered`；语言或主题读取失败时使用默认值。空数据及错误画面也按实际绘制完成通知，旧外观下的绘制回调不能提前通知截图。
- 界面、日期和时长支持中文、英文、日文，跟随飞书宿主语言。深色主题跟随宿主变化，全屏采用深色与透明外层背景；自选主题色仍保留。配置面板底部预留 70px。

## 代码结构与验证

`App.tsx` 组织界面，`TimelineChart.tsx` 管理图表，`hooks.ts` 管理异步状态，`lark-data.ts` / `lark-schema.ts` 负责 SDK 数据与结构，`time.ts` / `source-config.ts` 处理时间和配置规则。`echarts.ts` 仅注册甘特图所需模块。

`npm test` 覆盖原始时间与耗时边界、视图范围、跨页读取及分页失败、旧配置兼容和唯一标识移除、不完整配置修复、适配表自动选择、异步竞态、空数据与错误恢复、宿主外观延迟和失败时的截图通知、图表生命周期及缩放、提示内容转义、主题持久化。SDK 通过测试替身验证，真实飞书权限与数据仍需在仪表盘环境验收。

## 飞书环境验收

本地测试使用 SDK 替身，不能代替飞书服务端验收。发布候选版本后需在真实 Base 验证：无需唯一标识的首次创建与保存；旧组件直接显示；所选视图的数据范围；同名同时间记录独立计数；记录增删改自动刷新；复制模板后读取副本表；全屏及自动化截图。

2026-09-17 的历史版本已在独立测试 Base 实测创建、保存、展示、筛选、记录计数、耗时修改、复制和全屏；这不作为当前移除唯一标识版本的实测结论。官方翻译校对及发布后的自动化截图仍待完成。本地地址不能代替飞书服务端可访问的发布地址。
